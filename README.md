# Мониторинг добычи нефти и газа

Внутренняя система near-real-time мониторинга добычи для нефтегазовой
компании в Казахстане. Это **слой аналитики над SCADA** — собирает данные,
проверяет их, считает и показывает, но никогда ничего не пишет обратно в
контур АСУ ТП.

## Что умеет

- **Сбор данных** о добыче из разнородных источников (CSV/Excel, синтетика
  для разработки, заготовка под прямое подключение к АСУ ТП) в единую БД,
  с карантином для всего, что не удалось разобрать
- **Валидация замеров** дебитов на АГЗУ — 8 автоматических правил вместо
  проверки глазами в Excel
- **Аллокация** (back-allocation) — распределение суточной добычи узла
  сбора по отдельным скважинам
- **Расчёт потерь добычи** (deferred production) — потенциал минус факт,
  с разложением по причинам (простой, обводнение, снижение дебита,
  простаивающий фонд)
- **Алерты об аномалиях** — 8 детекторов (скважина встала, скачок
  обводнённости, аномалия давления, приближение МРП насоса и др.),
  с дедупликацией, автозакрытием, группировкой каскадных отказов и
  рассылкой в Telegram
- **REST API** — 12 эндпоинтов (FastAPI) с JWT-авторизацией, пагинацией,
  кэшированием тяжёлых запросов и автодокументацией (OpenAPI/Swagger)
- **Веб-дашборд** — 5 экранов (React + TypeScript + ECharts): утренняя
  сводка, карточка скважины, фонд скважин, анализ потерь, качество данных

## Чего система принципиально не делает

- Не пишет и не управляет контуром АСУ ТП — система строго read-only
- Не заменяет SCADA и не дублирует её функции реального времени
- Не разворачивается в облаке — только on-premise, внутри корпоративного контура
- Не принимает решения и не управляет автоматически — только информирует,
  решения принимает инженер

Полный список решений и почему они приняты — в [`CLAUDE.md`](./CLAUDE.md).

## Быстрый старт

```bash
# 1. Поднять БД
docker compose up -d

# 2. Установить зависимости и применить миграции
pip install -e ".[dev]"
alembic upgrade head

# 3. Сгенерировать тестовые (синтетические) данные
python scripts/generate_synthetic_field.py

# 4. Завести пользователя для входа в API/дашборд
python scripts/create_api_user.py --username <логин> --password <пароль> --role manager

# 5. Поднять API
uvicorn src.api.main:app --reload

# 6. Поднять дашборд (в отдельном терминале)
cd frontend && npm install && npm run dev
```

Дашборд откроется на `http://localhost:5173`, API — на
`http://localhost:8000` (документация — `http://localhost:8000/docs`).

## Структура репозитория

```
src/
  ingestion/    — сбор и нормализация данных из источников
  domain/       — доменные модели (скважина, узел сбора, замер и т.д.)
  calc/         — расчётные модули: валидация, аллокация, deferred production
  alerts/       — детекторы аномалий и жизненный цикл алертов
  api/          — FastAPI-приложение
frontend/       — веб-дашборд (React + TypeScript)
migrations/     — миграции схемы БД (Alembic)
scripts/        — генератор синтетических данных, служебные CLI
tests/          — тесты (pytest), структура зеркалит src/
docker/         — Dockerfile / init-скрипты для БД
```
