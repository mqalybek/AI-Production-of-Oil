# frontend

Дашборд мониторинга добычи: React + TypeScript + ECharts, светлая тема,
плотная инженерная вёрстка. Читает данные из `src/api/` (см. корневой
CLAUDE.md).

## Запуск для разработки

```bash
# 1. Поднять API (из корня репозитория)
uvicorn src.api.main:app --reload

# 2. Завести себе логин (один раз)
python scripts/create_api_user.py --username <логин> --password <пароль> --role manager

# 3. Поднять фронтенд
cd frontend
npm install
npm run dev
```

Dev-сервер Vite проксирует `/api/*` на `http://localhost:8000` (см.
`vite.config.ts`) — в браузере всё выглядит как один домен, как и будет
в проде за reverse-proxy.

## Структура

```
src/
  api/          — типизированный клиент к бэкенду (client.ts — fetch-обёртка
                  с JWT и обработкой 401, endpoints.ts — по одной функции на
                  эндпоинт, types.ts — TS-типы 1:1 с pydantic-схемами)
  auth/          — контекст авторизации (токен в localStorage)
  components/    — переиспользуемые куски интерфейса
  pages/         — один файл на экран
  utils/         — форматирование чисел/дат, экспорт в CSV, словари меток
```

## Экраны

1. Утренняя сводка (`/`) — план/факт, простаивающие скважины, топ-5 потерь,
   критичные алерты, тренд 30 суток
2. Карточка скважины (`/wells/:uwi`) — паспорт, графики добычи и
   телеметрии, шкала событий, таблица замеров
3. Фонд скважин (`/wells`) — таблица с фильтрами и экспортом в CSV
4. Анализ потерь (`/losses`) — Парето по причинам, разбивка, динамика
5. Качество данных (`/data-quality`) — метрики брака замеров

## Экспорт в Excel

Кнопка "Экспорт в Excel" на экране фонда скважин отдаёт CSV (с BOM, Excel
открывает нативно), а не `.xlsx` — библиотеки для генерации `.xlsx` на
npm (`xlsx`/SheetJS) имеют неисправленные уязвимости (см. CLAUDE.md).
